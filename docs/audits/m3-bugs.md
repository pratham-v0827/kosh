## Phase 4 audit scope (2026-11-15)

Everything M3 changed since `main` (import framework, statement parsers, dashboard, holdings, prices,
rules) was read with these questions: can a user lose or double-count holdings, can one user see or
change another's data, can a third-party source be hit harder than once a day per item, and does
any screen say something untrue. Each finding above has a test that failed before the fix (the
smoke checks were run against the old code to confirm).

Checked and found sound (no change needed):

- Import confirm: draft status, 24-hour expiry and double-confirm races are checked inside the
  ledger transaction; stale _replaced_ lots were already refused (409).
- Inputs: confirm and ticker-mapping bodies are bounded (≤ 500 mappings, tickers ≤ 20 characters
  with a fixed character set, so they cannot change a provider URL).
- Price history: only instruments the user holds (404 otherwise); the ticker comes from the stored
  instrument, whose id is always derived from that ticker, so one user cannot attach a wrong
  history to another's share. No user id is written to the shared documents.
- Privacy mode: every amount goes through the one formatter, including chart axes and tooltips;
  quantities are hidden too. The dollar view converts rupee amounts only.
- Holding page chart: the average-cost line is in the share's own currency, like its prices.
- Parsers: negative quantities are refused; zero quantities are set aside and the holding is
  removed, as a sale should.

Known limitations (documented, not bugs):

- Undoing a statement import removes what it added; it does not bring back the statement before it
  (`docs/parsers/groww-holdings.md`).
- Index history goes back ten years; purchases older than that get no index comparison, and the
  card says so.
- Market-cap categories come from AMFI's half-yearly list; shares listed since its date count as
  small cap until the next list.
